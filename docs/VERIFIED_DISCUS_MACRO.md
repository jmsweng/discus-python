# Verified DISCUS macro syntax (DISCUS_SUITE 6.23.01)

This document records the **empirically verified** macro syntax and CLI invocation for
the installed DISCUS_SUITE, so the `discuspdf` runner matches the real executable.

## Installed version

- **Executable:** `/usr/local/bin/discus_suite` (ELF 64-bit, dynamically linked)
- **Version banner:** `D I S C U S - S U I T E  Version 6.23.01`
- **Install route:** official `bbb_install_script.sh` (from the `tproffen/DiffuseCode`
  release) run inside the Ubuntu-22.04 WSL2 distro. The script downloaded the official
  `DIFFUSE_INSTALL.tar.gz` from the companion `rneder/DiffuseSuplement` repo and compiled
  the suite from source (the `code=pre` path fell back to a CMake/Fortran build on this
  system).
- **Note:** the installer pulls the *latest* release at run time, which was **6.23.01**
  (newer than the 6.22.01 referenced in the setup brief). The macro syntax below was
  validated against 6.23.01.

## Command-line invocation (verified)

The suite's own usage line is:

```
suite [-remote] [-debug] [-port=p] [-access=ip]
```

but the **suite manual** (`/usr/local/share/suite_man.pdf`, §1.2.5 "Command line options")
documents the macro-running options, which were confirmed to work:

```bash
# Run a macro file (auto-executes it on start):
discus_suite -macro run.mac

# Ignore any autorun.mac, then run the macro:
discus_suite -noautorun -macro run.mac
```

**Verified:** `discus_suite -noautorun -macro run.mac` exits 0 and produces the expected
output file. This is the invocation `PDFRunner` uses.

> The `discus_suite -h` / `--help` flags are **not** supported; `-h` is interpreted as a
> macro filename. Do not assume `--version` exists — read the banner from a normal launch.

## 1D atomic PDF macro (verified working)

In DISCUS v6 the 1D powder PDF is computed **from the powder pattern** (the old
`pdf` / `set range` / `calc` / `save pdf` menu is gone). The verified sequence is:

```text
# Generated by discuspdf: 1D atomic PDF calculation (DISCUS v6.x)
discus
read
cell model.cll,5,5,5
powder
reset
xray
set axis,q
set calc,debye
set qmin,0.5
set qmax,25.0
set dq,0.01
set delta,0.0
set wvle,1.5406
run
exit
output
outf result.pdf
form pdf, r, 0.0, 12.0, 0.02
value PDF
run
exit
exit
```

### How it was verified

1. A candidate macro using the **old** syntax (`pdf` / `set range` / `calc` /
   `save pdf,result.pdf`) was run and **failed** (`Unknown command` at the powder level,
   no `result.pdf` produced).
2. The suite manual (§3.2 Powder diffraction, §3.4 Output file formats) was consulted;
   it shows the v6 workflow: `powder` menu → `run`, then `output` menu →
   `form pdf, r, <rmin>,<rmax>,<dr>` / `value PDF` / `run`.
3. A corrected macro (above) was run with `discus_suite -noautorun -macro run.mac`:
   - exit code **0**
   - produced `result.pdf` with **601 lines** (r = 0.0 → 12.0 in 0.02 Å steps)
   - two finite columns: `r` (Å) and `G(r)` (PDF), strictly increasing `r`
   - physically plausible shape (negative at small r, rising to the first-neighbor peak)

### Parameter mapping (config → macro)

| `PDFConfig` field | macro command | notes |
|---|---|---|
| `supercell` | `cell model.cll,<nx>,<ny>,<nz>` | expands the unit cell |
| `radiation` | `xray` / `neutron` / `electron` | powder-menu radiation selector |
| — (fixed) | `set axis,q` | calculate on a uniform Q grid |
| — (fixed) | `set calc,debye` | Debye-scattering-equation powder mode |
| — (fixed) | `set qmin,0.5` | Q-grid start (Å⁻¹) |
| `qmax` | `set qmax,<qmax>` | **omitted when `qmax == 0`** (disables Qmax termination) |
| — (fixed) | `set dq,0.01` | Q-grid step (Å⁻¹) |
| `qsig` | `set delta,<qsig>` | Gaussian convolution width; `0.0` = off |
| — (derived) | `set wvle,<λ>` | 1.5406 Å (Cu-Kα) for xray; 1.5400 Å reference for neutron |
| `rmax`, `dr` | `form pdf, r, 0.0, <rmax>, <dr>` | PDF distance range and step |
| — (fixed) | `value PDF` | write the powder PDF |

## Output file format

`result.pdf` is a **plain-text, two-column** ASCII file (not an Adobe PDF):

```
   0.0000000000000000       -5.7961407286989876E-008
   2.0000000000000000E-002 -0.16329171800557765
   ...
```

- Column 1: `r` in Å (strictly increasing)
- Column 2: `G(r)`, the 1D powder PDF (DISCUS handles scaling/normalization)

`discuspdf.read_pdf()` parses this format (skips comment/blank lines, reads the first two
finite columns, and requires a strictly increasing `r`).

## PGPLOT / X11 note

The suite is linked to `libX11` and ships `pgxwin_server`. On WSL with `DISPLAY=:0` set,
an interactive launch opens a (often blank) PGPLOT X-window. This is **expected** and
harmless; the headless `discus_suite -noautorun -macro run.mac` invocation used by
`PDFRunner` does not require the window and writes `result.pdf` directly.

**Headless invocation (used by `PDFRunner.run()`):** to prevent the blank PGPLOT window
from appearing when a notebook cell runs a calculation, `PDFRunner.run()` launches the
suite with `DISPLAY` (and `PGPLOT`) cleared and `PGPLOT=none` set, so PGPLOT falls back
to a null device. The suite then prints harmless `xdpyinfo: unable to open display ""` /
`pgxwin_server: cannot connect to X server []` messages and continues; the calculation
completes (exit 0) and `result.pdf` is written. No window is opened.

> The notebook's *plots* are matplotlib (which uses the non-blocking `Agg`/inline
> backend in this venv — `tkinter` is not installed), so they render in the browser
> independently of DISCUS. The blank window was solely DISCUS's PGPLOT device.

## Qmax limit and wavelength (measured 2026-10-31)

**Limit.** A DISCUS powder pattern only exists up to a Q set by the wavelength (2θ ≤ 180°, Q ≤ 4π/λ). With DISCUS_SUITE 6.23.01 and this macro (GaAs 5×5×5, X-ray, qmin 0.5, dq 0.01, rmax 12, dr 0.02) the usable limit is slightly lower, Q·λ ≈ 12.3–12.4:

| λ (Å) | 4π/λ (Å⁻¹) | G(r) stops changing between Qmax (Å⁻¹) |
|---|---|---|
| 1.5406 (default X-ray) | 8.16 | 8.0 and 8.1 |
| 0.7107 | 17.68 | 17.0 and 17.5 |
| 0.2 | 62.83 | not reached up to 60 |

Above the limit `set qmax` has no effect at all: at λ = 1.5406 Å, Qmax 10, 12, 14, 15, 30 and 60 give G(r) identical to floating-point precision. DISCUS prints no warning. It is not a point-count limit (changing dq does not move it). `discuspdf` keeps the macro and the result unchanged but issues `QmaxLimitWarning` when `qmax * wavelength > 12.0`. Every default run (qmax 25, λ 1.5406 Å), including `examples/run_sample` (qmax 30), therefore effectively uses Qmax ≈ 8 Å⁻¹.

**Wavelength dependence above Q ≈ 8 Å⁻¹.** A shorter explicit wavelength raises the limit, but the result then depends on the wavelength:

| Qmax (Å⁻¹) | wavelengths compared (Å) | max relative difference in F(Q) | in G(r) |
|---|---|---|---|
| 8 | 1.4 vs 0.05 | 7e-16 | 4e-16 |
| 15 | 0.7107 vs 0.2 / 0.05 | 5.5e-2 / 2.4e-3 | 2.2e-1 / 9.6e-3 |
| 30 | 0.4 vs 0.2 / 0.05 | 6.4e-3 / 7.1e-3 | 2.9e-2 / 3.2e-2 |

Neutron radiation shows the same effect (Qmax 15, λ 0.2 vs 0.05: 2.4e-1 in G(r)), so it is not caused by X-ray form factors or anomalous scattering. F(Q) (written with `form powder, q` / `value F(Q)`) already differs, so the source is the DISCUS powder calculation (debye mode), not the PDF transform. Cause unknown; to be raised with the DiffuseCode maintainers. Until then, Qmax ≤ about 8 Å⁻¹ at the default wavelength is the range in which this macro gives wavelength-independent results.
