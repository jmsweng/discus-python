# DISCUS 6.23.01 single-crystal 3D output integration

This project has two distinct HDF5 reading paths:

1. **Native DISCUS 6.23.01 `form nexus` / common format:** [`read_discus_volume`](../src/discuspdf/discus_output.py) reads `/entry/data/data_values`, `data_corner`, `data_increment_vector`, cell metric and `data_type_with_bragg` from **actual** DISCUS output. Data are indexed in **hkl (reciprocal lattice units)**, not three Cartesian-Q coordinate arrays.
2. **Custom Cartesian-Q HDF5:** [`Diffuse3DRun.load_volume(...)`](../src/discuspdf/diffuse3d.py) is retained for files that truly contain three separate physical Cartesian-Q axis datasets. Its coordinate labels are supplied by the caller and do **not** independently verify their physical calibration.

## Execute a verified native DISCUS macro (one execution)

Use a macro that was **already run and checked** against your DISCUS installation. The verified C3 example is a Bragg-present monoclinic *Patterson* test; it is **not** a correlated-disorder 3D-ΔPDF benchmark.

```python
from discuspdf import Diffuse3DRunner
from discuspdf.discus_output import delta_pdf_fractional

runner = Diffuse3DRunner(
    output_filename="C3_total.h5",
    runs_directory="runs_3d",
)
prepared = runner.prepare(
    "spike_discus_3d/macros/C3.mac",
    assets=("spike_discus_3d/macros/mono2.cll",),
)
print((prepared.directory / "run.mac").read_text())

# Execute exactly once: rerunning in the same directory would overwrite output.
job = runner.execute(prepared, native_nexus=True)
volume = job.load_discus_volume()  # calibrated hkl + cell metadata from NeXus
assert volume.with_bragg == "bragg_present"

# For this crystal the result is a Patterson map, NOT a 3D-Delta PDF.
patterson = delta_pdf_fractional(volume, require_diffuse=False)
```

The `output_filename` must exactly match the macro's `output / outf ...` command. It can be any simple `.h5` or `.hdf5` filename; path traversal is refused. The configuration does not silently rename or rewrite the DISCUS macro.

The `native_nexus=True` mode checks the **real** `/entry/data` common/NeXus format, including coordinate-frame, reciprocal-space and Bragg metadata, cell validity and grid dimension data. Status `complete` means the declared file/schema was validated, **not** that its Bragg separation or quantitative 3D physics has been independently benchmarked. With neither native validation nor an `OutputSpec`, the state is `produced_unverified`.

For an already Bragg-subtracted, axis-aligned hkl volume generated by a verified macro:

```python
job = runner.execute(prepared, native_nexus=True)  # on a NEW prepared job only
vol = job.load_discus_volume()
result = delta_pdf_fractional(vol)     # refuses bragg_present by default
print(result.imaginary_ratio, result.friedel_relative_error)
r_angstrom = result.cartesian_length((0.3, 0.2, 0.1))
```

This second snippet is **illustrative**; prepare a new run and set the matching native output filename first. A Bragg-subtracted label in a file must still be verified experimently/numerically.

## Real end-to-end example: Bragg-subtracted diffuse (C1)

The following example was **actually executed** against DISCUS_SUITE 6.23.01 on 2026-10-28 (WSL2 Ubuntu 22.04). The C1 macro writes a Bragg-subtracted diffuse volume (`set aver,100`); the runner validates the native NeXus schema and `delta_pdf_fractional()` produces a finite 3D-ΔPDF.

```python
from discuspdf import Diffuse3DRunner
from discuspdf.discus_output import delta_pdf_fractional
import json

# The C1 macro (verified against DISCUS 6.23.01) writes C1_total.h5,
# C1_diffuse.h5 (Bragg-subtracted) and C1_diffuse_3dpdf.h5.
runner = Diffuse3DRunner(
    output_filename="C1_diffuse.h5",   # must match the macro's 'outf' command
    runs_directory="runs_3d",
)
prepared = runner.prepare(
    "path/to/C1.mac",
    assets=("path/to/gaas.cll",),
)
# Execute exactly once; the exact staged macro is the exact executed macro.
job = runner.execute(prepared, native_nexus=True)
status = json.loads((job.directory / "status.json").read_text())
assert status["status"] == "complete"
assert status["output_validation"]["native_nexus"] is True
assert status["output_validation"]["physical_validation"] is False

vol = job.load_discus_volume()
assert vol.with_bragg == "bragg_subtracted"
assert vol.values.shape == (65, 65, 65)
assert vol.is_axis_aligned()

# Fractional hkl FFT: finite result, no invented Cartesian-Q axes.
result = delta_pdf_fractional(vol)
print(result.imaginary_ratio)        # ~1.7e-16 (Friedel-merged by DISCUS)
print(result.friedel_relative_error) # 0.0
```

**Observed evidence (2026-10-28):** engine exit 0; `status.json` reports `complete` with `native_nexus: true` and `physical_validation: false`; the native reader reports `(65, 65, 65)`, `bragg_subtracted`, axis-aligned; `delta_pdf_fractional()` produces a finite complex volume with `imaginary_ratio ≈ 1.7e-16` and `friedel_relative_error = 0.0`. This validates the **runner interface and schema**, not the quantitative 3D-ΔPDF physics.

## Coordinate systems, supported geometry and errors

- Native files store `data_corner` and `data_increment_vector[:, k]` in hkl, not Cartesian Å⁻¹. The lattice lengths/angles determine the metric. `delta_pdf_fractional` uses the physically equivalent `dh dk dl / V_cell` normalization and real-space coordinate steps `1 / (N dh)`.
- Valid nonorthogonal cell metrics are supported for the **axis-aligned hkl FFT** and for converting fractional real-space vectors to Å. The cell **orientation convention** is not a measured experimental orientation matrix.
- The current FFT **rejects skewed reciprocal sampling**, uncentered grids, decreasing hkl increments, invalid cells, and Bragg-present input (unless `require_diffuse=False`, yielding a Patterson function). No implicit regridding occurs.
- Excessive imaginary FFT content raises the shared `FFTValidationError`, with `exc.result` holding the complex volume, physical axes, Friedel diagnostic, normalization and provenance. Use `raise_on_imaginary=False` only if you explicitly intend to inspect a warning and the retained complex result.
- For general orthogonal cells, `vol.to_reciprocal_volume()` can convert source hkl metadata into Cartesian Q. For nonorthogonal cells use the native fractional transform, not relabeled Cartesian Q arrays.

## Legacy/custom HDF5 outputs

`Diffuse3DRunner.execute(job, output_spec=OutputSpec(...))` still supports a custom HDF5 file with an intensity dataset and three **explicit** axis datasets. Use `job.load_volume(intensity_dataset=..., q_datasets=..., coordinate_system="cartesian_q", units="1/angstrom", preprocessing=(...))` only if those units/steps are separately verified. Do **not** combine `native_nexus=True` and `output_spec`.
