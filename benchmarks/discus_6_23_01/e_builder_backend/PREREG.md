# Builder-backend probe — pre-registered (DISCUS_SUITE 6.23.01)

Fixed **before** the engine run. `inputs/`, `runs.json`, `criteria.json`, `make_inputs.py` and `analyze.py` are
committed first and not changed afterwards; a failed criterion is reported as a finding, not tuned away. If a
criterion turns out to be wrongly specified, a new version is registered (v2, …) with the reason recorded here.

## Questions
The disorder builder (discus-disorder-builder) moves into discuspdf. Three things it asks DISCUS to do were
never run in DISCUS:

1. **`scat NAME, 0,0,0,0,0,0,0,0, b`** gives an atom name its own neutron scattering length (for isotope
   labels). Is it applied in a Fourier run, and is it still in effect for a later `powder` run
   (`FourierConfig(scattering_lengths=…)`, `PDFConfig(scattering_lengths=…)`)?
2. **VOID padding.** The builder pads every cell to the same atom count with atoms named `VOID`. Do they
   leave the 3D intensity and the 1D G(r) unchanged (no scattering, and no change of the PDF normalisation)?
3. **Powder PDF from a `.stru`** (`read stru`, new `PDFConfig` source). Does it give the same G(r) as the
   verified `read cell <file>,4,4,4` path on the same crystal?

All macros are generated by discuspdf (`FourierConfig.render`, `render_pdf_macro`) on this branch.

## Inputs (`make_inputs.py`)
fcc, a = 3.52 Å, 4×4×4 cells, all B = 1 Å² (`temp ignore` in the Fourier runs).

| Structure | Content |
|---|---|
| `mix` | 256 sites, 64 Cu drawn without replacement (seed 20261103), the rest NI |
| `relabel` | `mix` with every CU renamed **NI63**. DISCUS does not know NI63 and guesses it from its first two letters: Ni (b = 10.3 fm) |
| `void` | `mix` plus one `VOID` per cell at (¼, ¼, ¼): 5 rows per cell, 320 rows |
| `ni` | pure NI, 256 atoms (`.stru`), and the same crystal as a 4-atom P1 `.cll` read with `cell model.cll,4,4,4` |

Fourier: neutron (`neut`), `set aver,100`, grid h, k, l = −2…2 step 0.25 (17³, commensurate), 8-value seed.
PDF: rmax 10 Å, dr 0.02, Qmin 0.5, Qmax 7.0, dQ 0.01 Å⁻¹ (below the 12.3/λ limit), default λ.
`scat NI63` uses b = 7.718 fm, DISCUS's own value for Cu (`per_bcoh`), so a working `scat` makes `relabel`
scatter exactly like `mix`.

## Criteria (`criteria.json`)
| Key | Run(s) | Metric | Pass if |
|---|---|---|---|
| E0 | all | every run present with exit code 0, every committed input used and unchanged (LF), every log present | no problem |
| I0 | all | log lines matching `diffuse3d._ENGINE_ERROR_PATTERN` (tagged DISCUS messages such as `***FOUR***`) | informational: listed in the JSON, never a failure by itself |
| E1 | `f_mix` vs `reference_scattering.diffuse_intensity` (b Ni 10.3, Cu 7.718) — baseline | rel L2 | ≤ 1e-9 |
| E2 | `f_relabel_scat` vs `f_mix` | rel L2 | ≤ 1e-6 |
| E3 | `f_relabel_noscat` | max \|I\| / max \|I(f_mix)\| | ≤ 1e-6 |
| E4 | `f_void` vs `f_mix` | rel L2 | ≤ 1e-9 |
| E5 | Fourier runs | `bragg_subtracted` and 17×17×17 | all |
| P0 | PDF runs | r = 0…10 step 0.02 (501 points), finite G | all |
| P1 | `p_relabel_scat` vs `p_mix` | max \|ΔG\| / max \|G\| | ≤ 1e-6 |
| P2 | `p_relabel_noscat` vs `p_mix` | max \|ΔG\| / max \|G\| | **≥** 1e-4 (shows `scat` changed the powder run) |
| P3 | `p_void` vs `p_mix` | max \|ΔG\| / max \|G\| | ≤ 1e-6 |
| P4 | `p_ni_stru_n` vs `p_ni_cll_n` (neutron) | max \|ΔG\| / max \|G\| | ≤ 1e-6 |
| P5 | `p_ni_stru_x` vs `p_ni_cll_x` (X-ray) | max \|ΔG\| / max \|G\| | ≤ 1e-6 |

Reasoning for the limits: the D reference probe reproduced DISCUS neutron intensities on a commensurate grid to
2.5e-15 … 1.8e-13 relative L2 (E1, E4 allow 1e-9). E2 compares a length DISCUS parses from the macro with
its built-in table value; if either is kept in single precision, b differs by ≈ 8e-9 relative and the diffuse
intensity (∝ (b_Ni − b_Cu)²) by ≈ 5e-8, so E2 allows 1e-6, and a value between 1e-9 and 1e-6 is recorded as
"custom b stored in single precision", not as a failure. With all scatterers equal and atoms on the lattice,
`set aver,100` leaves only rounding; `value int` is double precision (E3). The Debye sums in P1, P3–P5 use the
same atom pairs with the same weights; only the summation order may differ, so 1e-6 is generous. P2: an
independent Debye-sum estimate on the actual `mix` structure (Q 0.5–7, r 0–10 step 0.02), b(Cu) 7.718 vs 10.3
on the Cu atoms, gives max |ΔG| / max |G| = 3.5e-3 normalised by ⟨b⟩² (1.5e-2 by ⟨b²⟩, 2.7e-2 with the Laue
term); the limit 1e-4 sits well below the smallest of these (registered in v1 after an independent review,
before any engine run).

`analyze.py --selftest` checks that consistent data pass and that each failure mode is caught (scat ignored,
NI63 read as something other than Ni, VOID scattering or entering the normalisation, `.stru` ≠ `.cll`, bad
metadata or r grid).

## What a failure would mean
* E1 fails → the baseline is wrong (the oracle, the grid or the run), not the feature; E2–E4 are then not
  interpretable.
* E2/P1 fail → `scat` not applied (or not kept for `powder`): the feature must not be offered.
* E3 fails → DISCUS does not read NI63 as Ni; the builder's isotope-label assumption is wrong.
* P2 fails → without `scat` the relabelled powder run already equals `p_mix`, so the powder G(r) does not
  distinguish the two lengths here and P1 cannot show that `scat` reaches the powder run (no power).
* E4/P3 fail → VOID padding changes the result; the builder must stop padding or correct for it.
* P4/P5 fail → `read stru` powder PDFs differ from the verified path; the `.stru` source must not be offered.
